# Markdown Presentation Rules

> [!NOTE]
> Lagoon documentation should be easy to scan in GitHub and easy for a new developer to follow.

## Required Shape

| Section | Purpose |
| --- | --- |
| Title | Clear document name |
| Callout | One short note about the document's boundary |
| Dashboard | Scope, status, owner, or verification at a glance |
| Main sections | Short chunks using tables and checklists where useful |
| Verification | Exact checks or an explicit reason no check applies |
| Stop points | What must not be assumed or built yet |

## Writing Rules

- Keep paragraphs to one to three sentences.
- Prefer tables for file maps, acceptance criteria, and phase boundaries.
- Use concrete file paths and commands instead of abstract instructions.
- Make in-scope and out-of-scope work visible.
- Use GitHub callouts for privacy, cost, safety, and irreversible decisions.
- Avoid decorative formatting that does not help a reader make a decision.

## Stop Point

These rules are a readability aid, not a substitute for product requirements or tests.
